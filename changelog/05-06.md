# Brainiac Changelog 05-06

## Version 6

**What changed**

- Defined `TODO.md` as a quick-capture dashboard: users create canonical
  checkboxes under `## Inbox` and a live Tasks query shows every other open
  task, grouped by source path.
- New managed vaults receive the standard dashboard during `brainiac init`.
- Made the no-copy rule operational: a dashboard may render a task, but its
  checkbox is edited only in its canonical source note.

### Verification

- The Tasks plugin is installed and enabled.
- `TODO.md` has `brainiac_role: source`, an `## Inbox` section, and an
  `## Open tasks` block containing:

  ```tasks
  not done
  path does not include {{query.file.path}}
  group by path
  ```

- If all conditions hold and `installed_version` is already `6`, this
  migration is complete.

### Migration

1. Create or resume `.state/migrations/v6.yml`:

   ```yaml
   status: in_progress
   current_step: todo_dashboard
   last_note: "Review and activate the TODO dashboard."
   ```

2. Inspect the vault-root `TODO.md`. Explain the exact planned change and ask
   for confirmation before editing it.
3. Back up the existing `TODO.md` under `.state/backups/`. Preserve each
   existing unfinished line by converting it to a checkbox under `## Inbox`.
   Do not copy tasks from other notes into Inbox.
4. Replace the rest of the page with the standard `## Open tasks` query. It
   excludes the current page, so Inbox tasks remain visible once and all other
   tasks are live references to their source checkboxes.
5. Re-open `TODO.md`, verify the Tasks plugin state, then mark the journal:

   ```yaml
   status: complete
   current_step: complete
   last_note: "TODO dashboard activated with canonical Inbox tasks."
   ```

6. Back up `brainiac_me.md`, then update `installed_version` to `6` only after
   validation.

### Validation

- `TODO.md` contains no copied task checkboxes from another source note.
- Its Tasks query excludes `TODO.md` and groups by path.
- A user can add a new checkbox under `## Inbox` without changing another
  note.
- `.state/migrations/v6.yml` is complete.
