# Brainiac Changelog 06-07

## Version 7

**What changed**

- Replaced the ambiguous sensitive-domain read-only wording with one explicit
  human-confirmation flow for every vault edit.
- Confirmed that health, family, finance, legal, credentials, and private
  operational notes do not need a special review skill and are not technically
  blocked once the user approves the exact change-set.
- Clarified that the missing CLI write command is an API boundary, not a ban on
  a user-confirmed agent file edit.

### Verification

- `brainiac.md` and `AGENTS.md` require an exact file-level change-set and
  explicit user confirmation before every vault edit.
- Neither file requires a special review skill for sensitive notes or claims a
  technical limitation based on sensitivity alone.
- `brainiac_me.template.md` and `INSTALLATION_VERSION` both use `7`.

### Migration

none — no vault data, configuration, or migration journal is required. The
normal upgrade flow advances `installed_version` only after validation.

### Validation

- A future operator may create or edit a health note after presenting the exact
  file-level change-set and receiving explicit user confirmation.
- A new `brainiac init` installation writes `installed_version: 7` and
  `last_local_version: 7`.
