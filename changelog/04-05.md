# Brainiac Changelog 04-05

## Version 5

**What changed**

- Added a visible, two-state session startup contract: `BOOTING` before
  routing and `LOADED` only after Brainiac is ready for ordinary vault work.
- Defined one bounded bootstrap read for the local config, setup state,
  personal context, and update-check state.
- Prohibited greetings, intermediate loading messages, broad vault reads, and
  ordinary work before startup routing is complete.
- Limited the ready-state options to Brainiac's current read-only and
  diagnostic capabilities.

### Verification

- `AGENTS.md` defines the exact `B R A I N I A C   S E S S I O N   B O O T I N G`
  banner as the only pre-contract user-facing message.
- `brainiac.md` defines the exact `LOADED` banner, the single bootstrap read,
  and every startup-routing gate.
- `brainiac_me.template.md` and `INSTALLATION_VERSION` both use `5`.

### Migration

none — no vault data, configuration, or migration journal is required. The
normal upgrade flow advances `installed_version` only after validation.

### Validation

- A new `brainiac init` installation writes `installed_version: 5` and
  `last_local_version: 5`.
- A new session cannot emit `LOADED` before config, setup, version, and
  applicable update-check routing have completed.
